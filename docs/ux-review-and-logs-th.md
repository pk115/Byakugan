# ทบทวน UX และหน้า Event Logs — Byakugan

วันที่: 11 พฤศจิกายน 2026

## ข้อสรุป

แอปมีความสามารถหลายด้าน แต่โครงสร้างนำทางและคำเรียกทำให้ผู้ใช้ใหม่เชื่อมโยงว่า “ติดตั้งอะไร → ข้อมูลอยู่ไหน → ต้องทำอะไรต่อ” ได้ยาก การปรับลำดับงานและข้อความควรมาก่อนการเปลี่ยนธีมหรือเพิ่มกราฟ

ผลนี้มาจากการอ่าน implementation และใช้งานแอปทดสอบด้วยข้อมูลจำลองผ่านเบราว์เซอร์ ไม่ใช่ผล usability testing กับกลุ่มผู้ใช้จริง และยังไม่ได้ตรวจข้อมูลบน Production

## สิ่งที่พัฒนาในรอบนี้

- เมนู “บันทึกเหตุการณ์ / Event logs” สำหรับ ADMIN, OPERATOR และ AUDITOR
- ปุ่ม “ดู Log” ที่แต่ละเครื่องใน Servers & Agents โดยเลือกเครื่องให้ทันที
- ค้นหา event, host, actor, IP และ details แบบข้อความย่อย
- กรอง Agent, source, severity, event, actor, IP, result และช่วงเวลา
- ค่าเริ่มต้นย้อนหลัง 24 ชั่วโมง พร้อม 7 วัน, ทั้งหมด และช่วงเวลาที่กำหนดเอง
- ตารางเวลาเกิดเหตุ เหตุการณ์ เครื่อง ผู้ใช้ IP ผลลัพธ์ และ severity พร้อมเปิด details JSON และเวลารับข้อมูล
- โหลดรายการเก่าครั้งละ 100 ด้วย cursor ตามเวลาและ ID; ไม่ดึงข้อมูลทั้งหมดในครั้งเดียว
- ข้อความอธิบายกรณีไม่มีข้อมูล พร้อมคำสั่ง Windows LogDryRun
- รองรับไทย/อังกฤษและเวลาแสดงผลตาม timezone ของผู้ใช้; ช่องกรอกช่วงเวลาใช้ timezone ของ browser และแจ้งไว้ชัดเจน
- แยกชื่อเมนู “มอนิเตอร์” กับ “ประวัติการตรวจสอบ” ให้ตรงหน้าที่ และลดการใช้คำว่าโปรเจกต์บนหน้ารายการมอนิเตอร์
- แก้ข้อความ Agent collection ให้ระบุว่ามี log และ scan findings ด้วย ไม่ใช่ส่งเฉพาะ metrics

ข้อจำกัดของหน้า Logs: ต้องกด Search/Refresh เอง, ไม่มี live tail, ไม่มีการบันทึกชุดตัวกรองหรือ export เฉพาะผลค้นหาในหน้านี้; ใช้ช่องทาง audit export เดิมได้ รายชื่อเครื่องมาจากรายการ Agent ที่ API ปัจจุบันแสดง จึงอาจไม่มี Agent ที่ถูก revoke ใน dropdown แต่ยังค้น log ด้วย hostname/text ได้

## ปัญหาที่พบและข้อเสนอเรียงตามความสำคัญ

| ลำดับ | สิ่งที่พบ | ผลต่อผู้ใช้ | แนะนำ |
|---|---|---|---|
| 1 | ความสามารถรับ log มีใน API แต่เดิมไม่มีหน้าดู | ติดตั้งแล้วไม่รู้ว่าข้อมูลไปอยู่ไหน | เพิ่ม Logs และทางเข้าจากเครื่อง — ทำแล้วในรอบนี้ |
| 2 | Dashboard/Monitors/Projects ใช้ชื่อใกล้กัน แต่เป็นคนละมุมมอง | ไม่รู้ว่าต้องเพิ่มหรือเปิดดูจากเมนูใด | ใช้ชื่อ Monitor ให้เหมือนกันทั้งฟอร์ม ปุ่ม และหน้ารายละเอียด; รอบนี้แก้ชื่อเมนู/หน้ารายการเบื้องต้น |
| 3 | หน้าแรกเป็นรายการ service monitors ไม่ใช่ภาพรวมระบบทั้งหมด | ผู้ที่ติดตั้ง Agent แล้วเห็นหน้าว่างอาจคิดว่าระบบยังไม่ทำงาน | ทำ Overview จริง รวมจำนวนเครื่องที่รายงานล่าสุด, service down, findings สำคัญ, log ล่าสุด และ backup ล่าช้า พร้อมทางไปแก้ไข |
| 4 | Servers & Agents ยังไม่มีหน้ารายละเอียดเครื่องที่รวม metrics/logs/scans/findings | ต้องสลับเมนูเพื่อดูเครื่องเดียวกัน | เพิ่มหน้าเครื่องพร้อมแท็บ Overview, Metrics, Logs, Scans และ Findings; รอบนี้เพิ่มทางลัด Logs ก่อน |
| 5 | Sidebar มีหลายรายการและต้องเลื่อน; จอเล็กเป็นเมนูแนวนอนที่ยาว | ฟีเจอร์ด้านล่างค้นพบยาก และเสียบริบทเมื่อเปลี่ยนงาน | จัดกลุ่มตามงาน พร้อมกลุ่มยุบได้ และใช้ drawer บนมือถือ |
| 6 | Audit รวม backup, restore, connectors, delivery, schedule และ asset controls ในหน้าเดียว | ต้องไล่หาปุ่มท่ามกลางข้อมูลหลายประเภท | แยกเป็นแท็บ Backup & Restore, Controls, Reports และ Delivery |
| 7 | หน้าสแกนแสดง Profile, Schedule, Threat intel และศัพท์หลายชุดพร้อมกัน | ผู้ใช้ไม่รู้ว่าต้องเลือก target อะไรและผลตรวจหมายถึงอะไร | ให้เลือก “เครื่อง → สิ่งที่จะตรวจ → โฟลเดอร์/image”; ซ่อนตัวเลือกขั้นสูงและอธิบายข้อจำกัด Windows/ไฟล์ที่ build แล้ว |
| 8 | ไทยและอังกฤษปะปนในปุ่ม สถานะ และคำอธิบาย | สร้างภาระในการตีความ โดยเฉพาะผู้ใช้ใหม่ | แปล flow ให้ครบทั้งหน้า เก็บ event code/CVE เป็นค่าดิบ แต่แสดงคำอธิบายภาษาคนประกอบ |
| 9 | ตัวหนังสือรองและชื่อกลุ่มเมนูมี contrast ต่ำบนพื้นหลังมืด | ข้อมูลที่ช่วยนำทางกลับอ่านยาก | เพิ่มความสว่างและขนาดข้อความรอง พร้อมตรวจ contrast และ keyboard focus ทั้งแอป |
| 10 | ข้อมูล “ไม่เคยรับ/เก่า/ไม่มีสิทธิ์อ่าน/ระบบปกติ” ยังไม่ได้แยกชัดทุกหน้า | ผู้ใช้ตีความว่าไม่มีปัญหา ทั้งที่ไม่มีข้อมูล | แสดง No data, Last received, ความสดของข้อมูลและขั้นตอนแก้ไข; อย่าใช้สีเขียวแทนความครบถ้วนของข้อมูล |
| 11 | การเปลี่ยนหน้าใช้ state ใน App.vue และไม่มี URL แยกงาน | รีเฟรชแล้วกลับหน้าเดิมไม่ได้ และแชร์หน้ารายเครื่อง/ตัวกรองไม่ได้ | เพิ่ม routing และ query string หลังออกแบบโครงสร้างหน้าใหม่ ไม่ผูก state ชั่วคราวไว้กับ URL โดยไม่มีแผน |

## โครงสร้างเมนูที่แนะนำสำหรับรอบถัดไป

1. ภาพรวม — สถานะรวมและงานที่ต้องทำ
2. เครื่องและบริการ — Servers, Service monitors, Check history
3. เหตุการณ์และความปลอดภัย — Event logs, Vulnerabilities, Incidents
4. Backup และ Audit — Backup/Restore, Controls, Reports
5. ตั้งค่า — Alert channels, Sharing, Users, System

ให้แต่ละหน้ามีคำอธิบายหนึ่งประโยค ปุ่มหลักเพียงหนึ่งงาน และย้ายงานตั้งค่าที่ใช้น้อยไปไว้ส่วนเพิ่มเติม แทนการวางปุ่มสำคัญเท่ากันทั้งหมด

## การตรวจสอบรอบนี้

- Unit tests ของตัวกรอง log, literal search ที่มี %/_ และ cursor ที่ timestamp ซ้ำ
- ทดสอบ API กับ anonymous, Viewer และ Auditor รวม invalid severity, date range และ cursor ไม่ครบ
- Browser: เลือก Windows Agent, โหลดจาก 100 เป็น 125 รายการ, กรอง Warning, เปิดรายละเอียด, empty state และลิงก์ดู log รายเครื่อง
- ตรวจ layout ที่ viewport มือถือ 390px และแก้การล้นขององค์ประกอบซ่อนในตาราง; ตารางกว้างเลื่อนภายในส่วนตารางได้
- ตรวจ typecheck, tests และ build ตามผลที่รายงานในแชต

ยังไม่ได้รื้อเมนูทั้งแอป เปลี่ยนธีม หรือเปลี่ยนหน้าแรกเป็น Overview ในรอบนี้ เพราะเป็นการปรับ workflow ที่ควรทำเป็นชุดหลังตกลงลำดับความสำคัญ
