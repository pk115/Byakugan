# จัดการข้อมูลและประวัติ

เข้า **ตั้งค่าระบบ → จัดการข้อมูลและประวัติ** ด้วยบัญชี ADMIN เลือกประเภทและอายุข้อมูล กดตรวจจำนวน แล้วพิมพ์ `DELETE HISTORY` ก่อนกดสำรองและล้าง

รองรับ Logs, ประวัติ Monitor, Host metrics/Inventory, Database metrics, Health transitions/WebSocket gaps ที่จบแล้ว, การส่งแจ้งเตือน, Incident ที่ปิดเคสและฟื้นตัวแล้ว และ Compliance ที่ RESOLVED

โหมดล้างประวัติเก็บค่าล่าสุดของ Monitor/Host/Inventory/Database แต่ละเครื่องหรือ Monitor ไว้ รวมทั้งรายการที่ยังไม่จบและข้อมูลช่องโหว่ การล้างประวัติไม่ทำให้การแจ้งเตือนปัจจุบันหายไป

## รีเซ็ตข้อมูลมอนิเตอร์

เลือกโหมด **รีเซ็ตข้อมูลมอนิเตอร์ — รวมรายการที่ยังเปิด** แล้วเลือกกลุ่มข้อมูล:

- ช่องโหว่: ลบ Findings ทุกสถานะ ผลสแกน และงานสแกนที่จบแล้ว ต้องจบหรือยกเลิกงาน QUEUED/RUNNING ก่อน และระบบตรวจซ้ำก่อนลบ ไม่เปลี่ยนตารางสแกนหรือโปรไฟล์
- รายการที่ต้องดำเนินการ: ลบ Compliance findings และ Backup policy findings ทุกสถานะ รวม OPEN/ACKNOWLEDGED
- Health Check: ล้างสถานะปัจจุบัน ประวัติการเปลี่ยนระดับ และ Compliance findings หมวด HEALTH โดยคงนโยบายและค่าตั้งต้นไว้ หลังล้างแสดง NO_DATA จนประเมินใหม่ ไม่แสดงว่าระบบปลอดภัยหรือปัญหาถูกแก้แล้ว

รีเซ็ตไม่กรองอายุข้อมูล ต้อง Preview และพิมพ์ `RESET MONITORING` เพื่อยืนยัน การเลือกทั้งรายการที่ต้องดำเนินการและ Health จะไม่นับหรือลบ Compliance ซ้ำ หลังสำเร็จหน้าแอพโหลดสถานะใหม่ทันที

ค่าล่าสุดของเครื่องและ Monitor ยังคงอยู่ รอบ Health Check ถัดไปสามารถสร้างการแจ้งเตือนจากข้อมูลเดิมได้ Agent หรือผลสแกนใหม่ก็สามารถสร้าง Findings ใหม่ได้หากยังพบปัญหา การรีเซ็ตไม่ปิด Agent, Monitor, นโยบายหรือตารางสแกน

ทั้งสองโหมดเก็บผู้ใช้ การตั้งค่า Agent/Monitor, Audit trail, หลักฐาน Backup/Restore และรายงาน ไม่ใช่ Factory reset การรีเซ็ตบันทึก Audit action `MONITORING_DATA_RESET` พร้อมขอบเขต จำนวนจริง และตำแหน่งไฟล์สำรอง

Preview ใช้ได้ 10 นาที เฉพาะ Admin ผู้สร้าง ใช้ได้ครั้งเดียว และไม่ครอบคลุมแถวที่เพิ่มหลัง Preview หากจำนวนข้อมูลเปลี่ยนต้อง Preview ใหม่ การล้างและบันทึก Audit เกิดใน Transaction เดียวกัน

ก่อนล้างจะสร้าง SQLite online backup ใน `<SUPAPULSE_DATA_DIR>/maintenance-backups/before-cleanup-*.db` หากสำรองล้มเหลวจะไม่ลบ ไฟล์นี้มีฐานข้อมูลทั้งหมดรวมข้อมูลส่วนบุคคลและ Secret ที่เข้ารหัสไว้ จัดสิทธิ์เช่นเดียวกับ Volume ฐานข้อมูล คัดลอกเก็บนอก Server พร้อมรักษา Master key เดิมแยกจากไฟล์สำรอง

ไฟล์สำรองนี้ไม่รวมไฟล์รายงาน และไม่ใช่ bundle สำหรับ `npm run restore` การกู้คืนต้องหยุดแอพทุก instance สำรองฐานข้อมูลปัจจุบันไว้ จากนั้นให้ผู้ดูแลแทนที่ `supapulse.db` ด้วยไฟล์ที่เลือกและนำ `supapulse.db-wal`/`supapulse.db-shm` ของฐานข้อมูลเดิมออกก่อนเริ่มแอพอีกครั้ง โดยใช้ Master key เดิมและสิทธิ์เจ้าของไฟล์เดิม การกู้คืนย้อนข้อมูลทั้งฐานกลับไปก่อนล้าง

ไฟล์สำรองอยู่ Volume เดียวกัน ใช้พื้นที่เพิ่ม และไม่ถูกล้างอัตโนมัติจากหน้านี้ การ DELETE ทำให้พื้นที่ใน SQLite นำกลับมาใช้ได้ แต่ขนาดไฟล์อาจไม่ลดลงทันที ไม่มีการ VACUUM อัตโนมัติ
