# วิเคราะห์ภาษาไทย–อังกฤษและการสลับภาษา

ตรวจจากโค้ดและเว็บทดสอบในเครื่อง วันที่ 11 พฤศจิกายน 2026 ไม่ได้เปลี่ยนข้อมูลบน Production

## ข้อสรุป

อาการภาษาแสดงแปลกเกิดจากทั้งข้อความที่ยังไม่เข้าระบบแปล และเส้นทางโหลดค่าภาษาที่ไม่เหมือนกัน ไม่ใช่ปัญหาฟอนต์อย่างเดียว การเพิ่มคำแปลเมนูเพียงไม่กี่รายการจึงไม่แก้อาการหลัง Login/Refresh หรือข้อความสถานะที่ค้างเป็นภาษาเดิม

แก้ข้อความคงที่ 483 จุดใน App และจัดคำแปลหน้าจอ 485 รายการไว้ใน `src/ui-copy.ts` ร่วมกับชุดคำแปลเดิมใน `src/i18n.ts` ตัวเลขนี้ไม่ใช่เปอร์เซ็นต์ว่าทุกข้อความในระบบได้รับการแปลแล้ว

## ปัญหาที่พบและการแก้

| ระดับ | จุดที่พบ | อาการก่อนแก้ | สิ่งที่แก้ |
|---|---|---|---|
| สูง | เส้นทาง Login/MFA เทียบกับ Refresh | หลัง Login ไม่โหลด Regional settings เท่ากับตอน Refresh จึงเห็นภาษาหนึ่งก่อน แล้วกลับไปอีกภาษาหลังโหลดใหม่ | โหลด Regional settings และ Health ทั้งสองเส้นทาง โดยใช้ภาษาที่บันทึกในบัญชี |
| สูง | ข้อความฝังใน Template | ไทยเฉพาะ Sidebar แต่การ์ด ปุ่ม Settings/Audit/Scan/Monitor ยังอังกฤษ | ย้ายคำคงที่เข้าตัวแปลที่ตอบสนองต่อ locale โดยไม่แก้ค่าข้อมูลจริง |
| สูง | ตรวจสถานะ Authentication จากข้อความ | API แปล “Authentication required” เป็นไทย แต่บางจุดยังเทียบประโยคอังกฤษเพื่อจัดการ Session | เพิ่ม ApiError ที่มี HTTP status และตรวจ 401 โดยไม่ขึ้นกับภาษา |
| กลาง | ตั้งภาษาเทียบกับกดบันทึก | เปลี่ยนค่าใน Select แต่ยังไม่บันทึก ทำให้ผู้ใช้ไม่แน่ใจว่ามีผลแล้วหรือไม่ | เพิ่มตัวเลือกภาษาใน Sidebar ที่บันทึกบัญชีทันที และเชื่อมตัวเลือกภาษาส่วนตัวใน Settings เข้าจุดเดียวกัน |
| กลาง | ภาษาเริ่มต้นบัญชีใหม่ | Schema เดิมให้ en-US แม้ตั้งภาษาเริ่มต้นระบบเป็นไทย | บัญชีใหม่จาก Setup, Admin และ OIDC JIT ใช้ค่าเริ่มต้นระบบ ไม่เขียนทับภาษาของบัญชีเดิม |
| กลาง | วันเวลา | หลายจุดใช้ toLocaleString() โดยไม่กำหนดภาษา/เขตเวลา จึงตาม OS หรือ Browser | รูปแบบวันเวลาในหน้าจอหลักใช้ locale ที่เลือกและเขตเวลาบัญชี/ระบบ พร้อมปีคริสต์ศักราช |
| กลาง | ป้าย Server time | ป้ายเขียน UTC แต่ค่าจริงแสดงตามเขตเวลาที่เลือก | แก้ป้ายให้ตรงกับค่าที่แสดง ส่วนวันที่หมดอายุใบรับรองระบุ UTC โดยตรง |
| กลาง | Health Check | ชื่อรายการเปลี่ยนภาษา แต่คำอธิบายการตรวจและความถี่ยังเป็นไทย | แปลคำอธิบายมาตรฐาน ความถี่ และหน่วยที่แสดงในตาราง โดยไม่เปลี่ยนเกณฑ์ตัวเลข |
| กลาง | รหัสสถานะ | OPEN/APPROVED/RESOLVED แสดงปนกับคำไทย | แปลป้ายสถานะ/ตัวเลือก แต่เก็บ value ที่ส่ง API เป็นรหัสเดิม ป้องกันบันทึกสถานะผิด |
| กลาง | ข้อความผลการทำงานที่เก็บเป็นประโยค | กดตรวจ/Export แล้วเปลี่ยนภาษา แต่ผลสำเร็จยังเป็นประโยคภาษาเดิม | เก็บข้อมูลผลตรวจ/Checksum แล้วประกอบข้อความตามภาษาปัจจุบัน |
| กลาง | หน้าสาธารณะและหน้าแชร์ | หลายคำฝังอังกฤษ และไม่มีตัวเลือกภาษาให้ผู้เยี่ยมชม | เพิ่มตัวเลือกภาษาฝั่ง Browser และใช้คำแปลในปุ่ม ป้าย สถิติ และสถานะ |
| กลาง | กล่องยืนยัน/ข้อความสำเร็จ | หน้าเป็นไทย แต่ Confirm/Alert บางงานเป็นอังกฤษ | เพิ่มคำแปลการลบ การเพิกถอน การยกเลิกสแกน MFA และการบันทึกค่าหลัก |
| ต่ำ | เมนูไทยยาวและพื้นที่ Footer | คำไทยตัดบรรทัด ชนกับตัวเลือกภาษา/ชื่อผู้ใช้ | ปรับขนาดและช่องไฟเมนู แยกแถวภาษาใน Sidebar และย่อคำเมนูบางรายการให้ชัดขึ้น |
| ต่ำ | คำศัพท์ไม่สม่ำเสมอ | ประวัติการตรวจมีชื่อหน้าคล้ายมอนิเตอร์ และคำออดิทหลายรูปแบบ | แยก Check history และใช้คำว่า “ออดิท” ในข้อความ UI ที่เกี่ยวข้อง |

## กติกาภาษาหลังแก้

1. ผู้เข้าสู่ระบบใช้ภาษาที่บันทึกไว้ในบัญชี การเปลี่ยนใน Sidebar บันทึกทันที และต้องคงอยู่หลัง Refresh/Login ใหม่
2. ค่าเริ่มต้นระบบใช้เริ่มต้นบัญชีใหม่และงานระบบ ไม่บังคับเขียนทับภาษาส่วนตัวของทุกคน
3. ผู้เยี่ยมชมหน้า Public/Share ใช้ตัวเลือกภาษาใน Browser ซึ่งไม่เปลี่ยนภาษาของบัญชีผู้ดูแล หากไม่เคยเลือก Browser เริ่มต้นเป็นไทยตามค่า fallback ของ Client
4. ข้อมูลดิบคงเดิม เช่น Hostname, CVE, ชื่อ Package, URL, ชื่อ Profile ที่ผู้ใช้ตั้ง, Error จากปลายทาง, ข้อความหลักฐาน และคำสั่ง/Token คำเหล่านี้ไม่ควรถูกแปลอัตโนมัติ
5. คำเทคนิคที่คงรูป เช่น CPU, RAM, HTTP, TLS, Trivy, PostgreSQL, MFA, ADMIN และ ISO ไม่ถือเป็นคำแปลตกหล่น
6. การเปลี่ยนภาษาไม่เปลี่ยนวันเวลาจริง หน่วยวัด ค่า Uptime สถานะที่ส่ง API หรือสิทธิ์ของผู้ใช้
7. ตัวเลือกสถานะใน Select เปลี่ยนเฉพาะ Label; value ยังคง OPEN, APPROVED ฯลฯ เพื่อรักษา Workflow

## ส่วนใบรับรองและสถิติที่แก้ควบคู่

- เพิ่มเมนูใบรับรองแยกที่หาเจอได้ ไม่ต้องเปิดฟอร์มเพิ่ม Monitor เพื่อค้นหาตัวเลือก SSL
- เก็บวันหมดอายุจริงจาก TLS peer สำหรับ HTTPS, WSS, Supabase และ SSL Monitor โดยตรวจ Host ที่ตั้งไว้ ไม่ตาม Redirect ไป Host อื่น
- การอ่านใบรับรองไม่เปลี่ยนการตรวจความถูกต้อง TLS ของ HTTP/บริการ หากใบรับรองไม่ผ่านจะแสดงแยก แม้ HTTP ที่ตั้ง Ignore TLS errors จะยัง UP
- เพิ่มวันหมดอายุ วันที่ตรวจ จำนวนวันคงเหลือ และแยก “ยังไม่ตรวจ/อ่านไม่ได้/ไม่ใช้ TLS” จากเลข 0 วัน ไม่ประมาณวันหมดอายุจากจำนวนวันที่ถูกปัดเศษ
- เปลี่ยนปลายทางแล้วล้าง Cache ใบรับรองเดิม และป้องกันผลตรวจเก่าที่กำลังวิ่งอยู่เขียนทับปลายทางใหม่
- ใช้สถิติชุดเดียวกันใน Detail, Public status และ Shared dashboard; หน้าอ่านอย่างเดียวรีเฟรชข้อมูลเป็นระยะ
- การ์ดหลักมี Response ปัจจุบัน, Response เฉลี่ย 24 ชั่วโมง, Uptime 24 ชั่วโมง, Uptime 30 วัน และใบรับรอง
- Uptime เป็นสัดส่วนผลตรวจ UP ไม่ใช่การวัดเวลาพร้อมใช้งานทุกวินาที; ไม่มีข้อมูลแสดง “—” ไม่ใช่ 100% และค่าเฉลี่ย Response ใช้ผลตรวจ UP
- วันที่หมดอายุแสดง YYYY-MM-DD UTC เพื่อคงวันอ้างอิงตรงกันทั้งภาษาไทย/อังกฤษ

## การทดสอบที่ทำ

- Unit tests รวม 112 tests: คำแปล/Key, การสลับ locale, HTTP 401 ที่ไม่ขึ้นกับภาษา, Enum values, TLS target/วันคงเหลือ, สถิติ และชุดทดสอบเดิม
- Integration บนฐานข้อมูลทิ้งได้: บันทึกไทย→อังกฤษแล้วอ่านจาก Session/Regional API, ค่าเริ่มต้นบัญชีใหม่, VIEWER เปลี่ยนภาษาตัวเองโดยไม่เปลี่ยนสิทธิ์, ใบรับรองในหน้า Private/Public และการล้าง Cache หลังเปลี่ยน Target
- HTTPS test server ใช้ใบรับรองทดสอบแบบ Self-signed: HTTP ที่เลือก Ignore TLS สามารถ UP แต่ certificateValid ต้องเป็น false และ strict HTTP ยังตรวจ TLS ตามเดิม
- ทดสอบหน้าเว็บจริง: English→ไทย→Refresh→English→Refresh, Detail, เมนูใบรับรอง, Health Check และ Public status
- ตรวจการ์ด 5 ช่องและวันหมดอายุจริงบนหน้าจอ ข้อมูลในภาพเป็นเครื่องทดสอบ ไม่ใช่ Production

## ข้อจำกัดที่ยังต้องแยกให้ออก

- ข้อความ Error เฉพาะของ Backend/ผู้ให้บริการและหลักฐานเดิมอาจยังเป็นภาษาเดิม การแปลอัตโนมัติอาจทำให้วิเคราะห์สาเหตุผิด จึงควรมีป้าย “ข้อความต้นฉบับ” และค่อยเพิ่ม Error code ที่แปลได้เป็นรายกรณี
- ค่าที่ผู้ใช้ตั้ง เช่น ชื่อสินทรัพย์ ชื่อหน้า Public หรือชื่อนโยบาย ไม่เปลี่ยนตามภาษา ไม่ใช่การแปลเมนูค้าง
- Native date picker, Password manager และกล่องที่ Browser/OS สร้าง อาจใช้ภาษาของ Browser/OS; แอพควบคุมได้เฉพาะ Label และวันเวลาที่แสดงเอง
- หน้าจอหลักใช้ปีคริสต์ศักราชให้ตรงกับวันหมดอายุและข้อมูลเทคนิค แต่หลักฐานเดิมหรือโปรแกรมอื่นอาจแสดงพุทธศักราช
- ยังไม่ได้ตรวจครบทุก Browser/OS/ขนาดจอ และทุกกรณีข้อความ Error ของผู้ให้บริการภายนอก จึงไม่อ้างว่าไม่มีอักษรต่างภาษาหลงเหลือในทุกสถานการณ์
- รายงานเดิมมีโครงสร้างคำแปลของตัวเอง Excel หลักฐานหลายชีทยังเก็บชื่อ Field และข้อมูลต้นทางเพื่อให้ตรวจเทียบได้; การเปลี่ยนภาษา UI ไม่แปลหลักฐานย้อนหลัง

การพัฒนาต่อควรเพิ่มคำแปลผ่าน Catalog/Dictionary และเพิ่มการทดสอบสลับภาษาของหน้าที่แก้ หลีกเลี่ยงการเทียบข้อความแปลเพื่อควบคุมสิทธิ์หรือ Workflow
